# 03 — Data Model v2 (target schema for the pilot)

> Status: DRAFT v1 — 2026-09-27. Baseline = Varun's `supabase/schema.sql` (becomes migration `0000_baseline.sql`, unchanged). Everything below is expressed as **deltas** in numbered migrations so history stays honest. Column types are Postgres. All tables: `id uuid pk default gen_random_uuid()`, `created_at timestamptz default now()`, `updated_at timestamptz` (trigger-maintained), RLS enabled.

Conventions: `deleted_at timestamptz null` = soft delete (views/queries filter it); money as `numeric(12,2)` + `currency char(3)`; enums as Postgres `enum` types (not text+check) from v2 onward; every FK indexed.

### 2.3 `catalog_brands` (new) / `catalog_models` (new) — ADR-06

`catalog_brands(id, name unique citext, slug, logo_media_id, status enum proposed/verified)`
`catalog_models(id, brand_id fk, name, series, scale, year, casting_code, color_variants jsonb, status enum proposed/verified/merged, merged_into_id fk self, proposed_by uuid, verified_by uuid, search tsvector generated)`
Unique index on `(brand_id, lower(name), coalesce(series,''), coalesce(scale,''))`. GIN on `search`. Policies: everyone reads `verified` + own proposals; admin writes; service role upserts proposals from AI scan.
**Car specs (0022_catalog_specs, MV-W08-prep, F-25/D-075):** `specs jsonb not null default '{}'` — keys `power_kw, torque_nm, weight_kg, zero_to_100_s, top_speed_kmh, drivetrain (fwd|rwd|awd), drag_cd, model_year`, all optional, bounds enforced by the immutable `catalog_specs_valid(jsonb)` behind a CHECK (same rules as `carSpecsSchema`); `specs_source text ≤ 80`, `specs_proposed_by uuid fk`, `specs_verified_by uuid fk`, `specs_verified_at timestamptz` (NULL = proposal, D-008). The specs columns change only inside `propose_catalog_specs(model, specs, source)` (any member or the service role; refused with `specs_already_verified` once verified — verified wins) and `verify_catalog_specs(model, specs, source)` (admin); a guard trigger (`mv.catalog_specs_rpc` GUC) refuses direct writes even by admins. Events `catalog.specs_proposed` / `catalog.specs_verified` (entity `catalog_model`). Fantasy castings keep `{}` and race on their segment archetype; `segment` itself lands with 0016 races (W08).

### 2.6 `marketplace_listings` (modify heavily → effectively v2)

Drop denormalised `seller_type/photo/name/location/mobile` (join `public_profiles`), drop `offers jsonb` (→ `offers` table).
Add: `catalog_model_id fk null`, `listing_type enum sale/trade/both`, `currency char(3) not null`, `country_code char(2) not null` (from seller at publish), `min_offer numeric` (derived: seller may set; default = price), `description text`, `view_count int default 0`, `favorite_count int default 0` (trigger), `offer_count int default 0` (trigger), `expires_at timestamptz` (pilot: 60 days, renewable), `sold_at`, `sold_offer_id fk offers`, `updated_at`, `deleted_at`, `search tsvector`.
Status enum: `draft/active/reserved/sold/expired/removed` — deployed as `active/sold/removed/reserved` through S8 (D-058); `expired` added in 0011 together with the hourly `expire_listings()` that sets it (D-099). `draft` is still not a deployed value.
**Constraint:** trigger `enforce_active_listing_limit()` before insert/update to `active` → count active listings for seller vs `entitlement_listing_slots(seller_id)` (base 2 + purchased slots, unlimited if Pro). DB is the last line; UI asks entitlements first.
Indexes: `(status, country_code, created_at desc)`, `(seller_id, status)`, `(brand)`, `(catalog_model_id)`, GIN `search`.

### 2.7 `offers` (new; replaces jsonb)

`id, listing_id fk, buyer_id fk, seller_id fk (denorm for RLS), type enum cash/buy_now/trade, amount numeric, currency, trade_item_ids uuid[] (buyer's public items), message text (≤ 500), status enum pending/accepted/declined/withdrawn/expired/completed/cancelled, responded_at, completed_at, expires_at (72 h), created_at`
Rules (enforced in `domain/deals` and by CHECK/trigger where cheap):

- cash offer ≥ `listing.min_offer` when `open_to_offers`; `buy_now.amount = listing.price`
- one `pending` offer per buyer per listing (partial unique index)
- rate limit: ≤ 5 offers/hour/buyer, ≤ 20/day (SQL function `check_offer_rate_limit()` in trigger)
- accepting an offer sets listing `reserved`, auto-declines other pending offers (emits events), opens chat
- `completed` = seller marks sold; `sold_offer_id` set; review window opens
  Policies: buyer or seller read; buyer insert (with `buyer_id = auth.uid()`); status transitions only via `rpc transition_offer()` (SECURITY DEFINER with role checks) — no direct update policy.

### 2.8 `deal_messages` (new)

### 2.36 `quests` (new, reference, seeded) — F-26, 0014

### 2.39 `token_ledger` FIFO columns (modify) — F-26, D-070, 0014/0014b

`remaining int` (credits: the unconsumed part; null on debits) and `consumed_earned int` (debits: how much came from earned credits; null on credits) — the only two columns the ledger ever updates in place, and only inside the RPCs (`token_consume_fifo`). `token_ledger_source` gains `mixed` (a spend funded by both). Spends: earned-first, `source` = earned / purchased (= any non-expiring credit) / mixed; refunds and negative adjustments: non-expiring-first; a credit first pays off a negative balance (D-065), so Σ `remaining` = max(balance, 0). Partial index `token_ledger_remaining_idx (user_id, created_at, id) where remaining > 0`; `domain_events_actor_type_time_idx (actor_id, type, occurred_at)` for the consumer's recounts. 0014b backfills both columns for pre-existing rows chronologically.

### 2.41 `world_earn_freezes` (new) — F-26/F-28, 0014c

`user_id pk → profiles, frozen_by → profiles null, note (≤ 280), created_at`. Admin-only read; **no write policies** — `admin_set_earn_freeze(user, frozen, note)` only (events `user.earn_frozen` / `user.earn_unfrozen`, admin actor). `earn_tokens()` returns NULL (nothing written) while a row exists; quests and season points still track. The global freeze is the `world_earn` flag audience (D-077). `world_open_garages` (0013b view) gains a trailing `spotlight_until` (max active Spotlight expiry, 0014c).

### 2.42 `job_runs` (new) — F-26 / ops, 0014d (+ 0011 H1 jobs)

`id bigint identity pk, job text (^[a-z][a-z0-9_]{1,59}$), triggered_by text cron/edge/manual, run_at timestamptz (the instant the job reasoned about), started_at, finished_at null, status text running/ok/error, result jsonb default {}, error text null`. Indexes `(job, started_at desc)`, `(started_at desc)`. Admin-only read; **no write policies** — `run_world_job()` is the only writer (one row per job per run; a failing job keeps its row with `status = error` + the SQLSTATE and message). ### 2.43 `clubs` + `club_members` (new, schema only) — F-22, 0015

`clubs`: `id, slug citext unique (^[a-z0-9_]{3,24}$), name (2–60), owner_id → profiles, join_mode enum open/apply/invite, country_code → countries null, description (≤ 500), banner_media_id → media null, created_at, updated_at`. `club_members`: `(club_id, user_id) pk, role enum owner/admin/member, status enum active/pending/banned, joined_at`. ### 2.44 `meetups` (new) — F-23, 0015

`id, host_id → profiles, club_id → clubs null, garage_user_id → world_garages null (= the host), kind enum virtual/in_person (virtual only until 0017), title (3–80), theme (≤ 60) null, description (≤ 1000) null, starts_at, ends_at (> starts_at, ≤ +6 h), capacity (2–500), showcase_limit (1–5, default 3), visibility enum public/followers/club/invite, status enum draft/scheduled/live/ended/cancelled, fee_paid int, fee_ledger_id / refund_ledger_id → token_ledger null, scheduled_at / started_at / ended_at / cancelled_at, created_at, updated_at`. Indexes `(status, starts_at)`, `(host_id, starts_at desc)`, `(club_id)`. Read = `meetup_visible(id, viewer)`: host / co-host / admin always; otherwise not a draft, no block with the host, and public (anon included) / follower of the host / active club member / directly invited / already holding an rsvp row. ### 2.45 `meetup_rsvps` + `meetup_invites` (new) — F-23, 0015

### 2.46 `meetup_showcase` (new) — F-23, 0015

Read follows meetup visibility; **no write policies** — `set_meetup_showcase(id, item_ids[])` replaces the caller's picks (room member, meetup scheduled / live, ≤ `showcase_limit`, every item the caller's own + public + not deleted).
